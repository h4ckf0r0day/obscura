# Worker Cancellation Evidence

## Current Implementation
- Worker agent uses tokio::select! between browser execution and lease-loss signal.
- On lease loss: fail_job called, renewal task aborted.
- Browser child process: NOT explicitly killed on lease loss (select! drops the future but child process continues until completion).
- Gap: supervised browser process is not terminated on ownership loss.

## Recommendation
- Add worker handle tracking in supervisor.dispatch to enable kill() on lease loss.
- Or use process-level timeout as fallback.
