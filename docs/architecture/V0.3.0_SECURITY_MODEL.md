# v0.3.0 Security Model

## Authentication
- Clients: API keys / JWT (established library). Control plane validates per request.
- Workers: mTLS or signed registration tokens; worker identity bound to registration record.
- NATS: NKey/JWT auth; per-account authorization.
- PostgreSQL: least-privilege roles; control plane uses app role; migrations use admin role.

## Tenant isolation
- Every job/worker/session row has tenant_id.
- All queries filter by tenant_id (application-level).
- Optional PostgreSQL RLS as defense-in-depth.
- Cross-tenant access returns 404 (no existence leak) + audit event.

## Secrets
- Stored in environment/secret manager, never in DB plaintext.
- CDP token, DB credentials, NATS creds injected at deploy time.

## TLS
- Client↔control plane: TLS 1.3.
- Worker↔control plane: TLS.
- NATS: TLS.
- PostgreSQL: TLS.

## Audit
- All mutating operations write audit_events.

## SSRF
- Inherited from Obscura (obscura-ssrf). Control plane validates URLs before dispatch.

## Resource limits
- Per-tenant job quotas, worker capacity, request size limits.
