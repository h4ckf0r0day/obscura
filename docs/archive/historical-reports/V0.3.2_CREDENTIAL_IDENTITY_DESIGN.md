# V0.3.2 Credential Identity Design

## Principal
- Fields are private (subject, tenant_id, is_admin, is_worker).
- Read-only accessors: subject(), tenant_id(), is_admin(), is_worker().
- Constructors are pub(crate): service, tenant, worker.
- External crates cannot fabricate principals.

## Credentials
- Table: credentials (credential_id PK, subject, tenant_id FK, secret_hash, is_admin, is_worker, revoked, expires_at).
- Secrets stored as SHA-256 hash (hex). Verified by hashing input and comparing.
- authenticate(credential_id, secret) -> Result<Principal>: validates format, resolves record, verifies hash, checks revocation/expiry, constructs Principal internally.
- revoke_credential marks revoked.
- create_credential stores hash.

## Service Identity
- ControlPlane::service_principal(name) is the only way to create service principals externally.
- Scheduler uses service_principal("scheduler"), worker agent uses "worker-agent", internal uses "internal".

## Limitations
- SHA-256 is not ideal for password hashing (should use Argon2/bcrypt for low-entropy secrets), but acceptable for high-entropy API tokens.
- No credential rotation endpoint yet.
- No HTTP API; auth is library-level.
