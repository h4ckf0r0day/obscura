# V0.3.2 Security Closure Implementation Report

## Changes
- Principal fields made private with read-only accessors.
- service_principal now requires bootstrap secret from env.
- create_credential and revoke_credential require &Principal with is_admin check.
- authenticate uses subtle constant-time comparison.
- SHA-256 hashing for credentials.
- Revocation and expiry enforced.

## F2/F3 Status
- F2: PARTIALLY RESOLVED (service identity now requires bootstrap secret; credential verification exists).
- F3: PARTIALLY RESOLVED (authorization enforced in protected methods; credential management now requires admin).

## Remaining
- No HTTP/network boundary yet.
- No credential rotation yet.
- No audit logging for credential operations.
- SHA-256 not ideal for low-entropy secrets.
